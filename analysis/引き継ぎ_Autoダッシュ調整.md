# 引き継ぎ: Auto ダッシュタイミングの調整

調整するのは **数値だけ**です。コードは触りません。

## どこを直すか

`scripts/guardCancel.lua` の **`DASH_AUTO_TICKS`**。1 か所だけです。

```lua
local DASH_AUTO_TICKS = {
	--                      f    b    fc   bc
	[0x05] = { name = "Morrigan",  f = 12, b = 12, fc = 10, bc = 12 },
	...
}
```

| 列 | 意味 |
|---|---|
| `f` | 前ダッシュ。**2 回目のタップからボタンまで**のティック数 |
| `b` | 後ろダッシュ。同上 |
| `fc` | 前ダッシュ中断。**逆方向(back)からボタンまで**のティック数 |
| `bc` | 後ろダッシュ中断。**逆方向(forward)からボタンまで**のティック数 |

**単位はゲームのティック。**メニューの `Guard Action Delay (Ticks)` に直接
打ち込む数字とまったく同じものです。表の値を書き換えるのと、メニューにその
数字を入れるのは同じ結果になります。

`0` は「モーションと同時に押す」。

**3 表示フレーム = 4 ティック**です。表示フレームで測った値を持ってきたら
×4/3 してください。

## いま何が確かで、何が確かでないか

| | 状態 |
|---|---|
| `f` / `b` | 旧ビルド(2026-06-25)で**実機調整済み**。ただしモリガン以外は本ビルドで未検証 |
| モリガンの `f` / `b` = 14 | 本ビルドで**確認済み**(13 では出たり出なかったりする ― 下の注意参照) |
| **サスカッチ全 4 項目** (`f=2 b=1 fc=7 bc=7`) | **本ビルドで実測済み。基準キャラとして使えます** |
| 他 13 キャラの `fc` = 10 | **根拠なし。**旧ビルドの `cancel_frame` から持ってきたが、あれは「逆方向をいつ入れるか」であって別の意味の数値。**ここが本命の調整対象** |
| `bc` | **未実測。**暫定で `b` と同じ値を入れてあるだけ |
| デミトリ (0x01) | **行が無い。**`fc`/`bc` は**測らないでください** — 攻略 wiki に「前ダッシュ/後ダッシュとも**中断不可**」とあり、技自体が存在しません。`f`/`b` は未実測なので、必要なら足せます |

## 触ってはいけないもの

* **逆方向の入れ方。**ダッシュ中断の逆方向は、シーケンスの最後のエントリと
  して**押しっぱなし**にしてあります(`controller.lua`)。攻略 wiki が
  「認識するタイミングは 1F のみだが、ダッシュした直後から入れっぱなしで
  問題ない」と書いている通りで、**タイミングを当てにいく必要はありません。**
  ここを「何フレーム目に入れる」方式に戻すと 1F の窓を外し始めます。

  ダッシュ中断のシーケンスは**前ダッシュ/後ろダッシュとまったく同じ 3 つ**
  です。逆方向はシーケンスに入っておらず、ティックフックが**ダッシュが出た
  2 ティック後**に倒してそのまま保持します。`fc`/`bc` は**そこからボタンまで**
  の間隔です。

  ```
  free+0  ダッシュ方向 (2 回目のタップ)
  free+1  ダッシュ方向        <- ここでダッシュが立つ
  free+2  逆方向 (保持開始)
  free+2+fc  逆方向 + ボタン
  ```

  **2 回目のタップが free+0 に落ちないとダッシュが出ません。**これは実測で
  確認済みで、1 ティックずれただけで `$06` が 0x14 にならず通常技になります。
  シーケンスを長くすると配送が間に合わずここがずれるので、**エントリを増や
  さないでください。**
* **モーションの前後に空エントリを積むやり方。**ディレイはティックフックが
  押しの位置として適用します。空エントリで表現しようとすると二重に効いて
  モーションが壊れます(過去に踏んで直した経緯があります)。

## ダッシュが出ない場合(数値調整とは別の話)

`DASH_AUTO_TICKS` はボタンの位置しか動かしません。**ダッシュ自体が出ない**
ときは別の 3 つを見ます(すべて `guardCancel.lua`)。

```lua
BACK_TAP_NEUTRAL_TICKS = 4   -- 後ろダッシュ前にレバーを離す長さ
BACK_TAP_HOLD_TICKS    = 2   -- 1 回目のタップを何ティック持つか
BACK_TAP_BIAS          = 3   -- タップを何ティック早く置くか
```

**後ろダッシュ専用**です。ダミーはガードで back を握っているので、離してから
押し直さないと押しエッジが立ちません。前ダッシュは握っていないので無関係。

出方が不安定なら **`BACK_TAP_BIAS` を 1 上げる**のが安全です。タップが署名
ティック(free-1)に乗ると必ず失敗し、早すぎるぶんには 10 ティック手前でも
成立するので、**外れる向きを早い側に倒す**のが正解です。

サスカッチで弱/中/強すべて安定することを確認済み(2026-08-20)。

## 数えるときの注意 ― ボタンが 2 回出ることがあります

`joypad.set()` が注入と同じ入力を**1 ティック遅れ**でも届けるため、押しが
1 ティックだけのとき**入力履歴にボタンが 2 個**出ることがあります。

**この 2 個目でも技は出ます。**そのため「N で出た」と見えても、実際に効いて
いるのが **N+1** ということが起こります。モリガンで実際に起きました
(13 で出たり出なかったり → 14 が本当の値)。

**判断のしかた:**

* 入力履歴のボタンが **1 個で安定して出る値**を採ってください。
* **2 個出ているときは、その値は 1 小さい可能性**があります。1 つ上げて、
  1 個で出るか確かめてください。

## 調整のしかた

1. FBNeo を起動し、Lua ホットキー **1** でメニューを開く。
2. **Player** タブ:
   - `Guard Action Type` = `Reversal - Specified`
   - `Reversal/Counter Input Motion` = `Forward Dash`(調べたい種類)
   - `Reversal/Counter Button` = 任意
   - `Guard Action Frequency` = `100%`
   - `Guard Action Delay (Ticks)` = **数字を直接入れて探る**
3. P2 にその技をガードさせる / くらわせる。
4. 出る最小の数字が見つかったら、それを表のその列に書く。

**メニューで直接数字を探ってから表に書き写す**のが早いです。Auto は表の値を
メニューに入れるのと同じことをしているだけなので、探索はメニューでやって
結果だけ表に反映すれば済みます。

`Auto` は 4 種類のダッシュのときだけ選べます。左右キーで 0..50 の手動値に
いつでも移せます。

## ログで裏を取りたい場合

`scripts/reversal_logs/kd_*.json` に記録されます。設定(`gc_delay`,
`counter_attack_stick_dummy`)も一緒に入るので、後から突き合わせられます。

`analysis/dash_delay.py` を走らせると、ダッシュが何ティック続いたか、ボタンが
その中に入ったかを出します。攻撃が出たかどうかは `$105`(トレースの `at`)で
判定できます — `$06` はダッシュ中ずっと `0x14` のままなので使えません。
ダッシュ攻撃はダッシュ状態の中のジャンプ技だからです。

**次のテストの前に必ず `python analysis/archive_logs.py` を実行**して、
前回のログを退避してください。2 つのバージョンのログが混ざると平均が意味を
失います。
