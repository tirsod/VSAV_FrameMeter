# VSAV 解析メモ ― アドレスと時間の扱い

Vampire Savior (CPS2, 970519 Japan) をトレーニングモードから調べた結果のうち、
**確定しているものだけ**をまとめたものです。経緯は省いて事実だけ載せています。

P1 のオブジェクトは `0xFF8400`、P2 は `0xFF8800`。以下 `$xx` は
オブジェクト先頭からのオフセットで、P2 なら `0xFF8800 + $xx`。

---

## 1. 時間の単位

**ゲームは 1 ティックごとに入力を読み、状態を進めます。**表示フレームとは別物です。

```
ターボ3   3 表示フレーム = 4 ティック
```

攻略 wiki の「ターボ3 = ノーマル × 0.75」と同じことを逆から言った関係です。
**攻略 wiki のノーマルスピードの F 表記は、そのままティック数として読めます。**

`0xFF8081` が 1 ティックごとに +1 されるカウンタ(ROM `0x008E10`)。
これが解析の時計になります。ラン・アヘッドが有効だと巻き戻るので、
逆行を検出したい場合はこの値の差分を見ます。

### 押しと行動

```
ティック X で押しのエッジが立つ  ->  行動はティック X+1
```

373 スパンで例外なし。`$126` = `~$124 & $122`(新しく押されたビット)。

## 2. ティック単位で動く方法

**これが中核です。**Lua から見える「フレーム」ではゲームの時間を追えません。

### CPU のアドレスにフックを掛ける

FBNeo の Lua には**命令アドレスにフックを掛ける関数**があります。

```lua
memory.registerexec(0x02211A, function() ... end)
```

**68000 がそのアドレスを実行するたびに呼ばれます。**フレームのコールバック
(`registerBefore` / `guiRegister`)は表示フレームに 1 回しか回りませんが、
これは**ゲームロジックが進むたび、つまり 1 ティックに 1 回**回ります。

**ここが出発点です。**トレーニングモードの時間の単位を「表示フレーム」から
「ティック」に変えられるのは、この 1 点があるからです。

使っているフック:

```
0x02211A   入力の消費。ここに置いた処理が、その回に読まれる入力を決める
0x0221CC   トレース採取
0x02760E   プッシュブロックの回数比較(レジスタを書き換える例)
```

**このルーチンはオブジェクトごとに回ります。**どちらのプレイヤーの回かは
`A6` で分かるので、必ず確認してください。

```lua
if memory.getregister("m68000.a6") ~= 0xFF8800 then return end   -- P2 以外は無視
```

レジスタは読むだけでなく**書き換えられます。**プッシュブロックの必要回数を
変える処理は、ゲームの比較命令の直前で `D0` を書き換えています。

```lua
memory.registerexec(0x02760E, function()
  if memory.getregister("m68000.a6") ~= 0xFF8400 then return end
  if memory.getregister("m68000.d0") < min_inputs then
    memory.setregister("m68000.d0", 0x00000000)
  end
end)
```

`memory.registerwrite(addr, len, fn)` もあり、**特定アドレスへの書き込み**で
発火します。1 表示フレームに複数回起きる変化を捉えるのに使えます。

### 経過ティックを数える

フックは「今このティック」を教えてくれますが、**何ティック経ったか**は別に要ります。

```
0xFF8081   1 ティックごとに +1 されるカウンタ ( ROM 0x008E10 )
```

これを基準にすれば、待ち時間も間隔もすべてティックで書けます。
差分は `(now - then) % 256` で取ります。

**ラン・アヘッドが有効だとこの値は巻き戻ります。**前のティックから 1 増えて
いない場合は、エミュレータが状態を復元して同じティックを再実行しています。
**「経過時間」をフレーム番号や Lua 側のカウンタで持つと、この再実行で
狂います。**このカウンタで持てばゲームと一緒に巻き戻るので狂いません。

### ラン・アヘッドは切ってもらう

**ラン・アヘッドが有効だと、最速行動が安定して出せません。**

エミュレータが同じティックを何度も実行するため、こちらのフックも同じ回数
呼ばれます。**「このティックで押す」という判断が、1 回のはずが複数回起きる**
わけです。押しエッジは 1 ティックにしか立たないものなので、
再実行された回のどれで書き込みが確定するかによって、狙ったティックから
ずれます。**free+0 に置いたつもりのものが free+1 に落ちれば、非必殺技は
出ません。**

実測では、ラン・アヘッド 1 フレームでティック対の **24.4% が逆行**し、
深さは 1〜2 でした。4 回に 1 回ずれる時計の上では、1 ティックの精度は出せません。

そのため画面に警告を出しています。**FBNeo の Run-ahead を Disabled にして、
エミュレータを再起動してもらう**必要があります。

### 有効かどうかの判定方法

**FBNeo は Run-ahead の設定を Lua に見せません。**そこで設定を訊くのではなく、
**挙動から判定します。**

`0xFF8081` は 1 ティックに 1 回 +1 されるので、**前の値から +1 以外の変化を
したら、それは再実行です。**

```lua
local _step = (lg - last_lg) % 256
if _step ~= 1 then
  -- 巻き戻り。深さは (last_lg - lg) % 256
end
```

**1 回の逆行では警告を出しません。**セーブステートの読み込みでも同じことが
起きるためです。**継続的な割合**を条件にしています。

```
逆行が 20 回以上、かつ全ティックの 5% 以上
```

この 2 つを満たしたときだけ画面上部に赤帯を出し、逆行率と最大の深さを
表示します。

## 3. 入力をメモリに書く

狙ったティックに入力を置くには `joypad.set()` では届きません。

### なぜパッド経由では届かないか

入力の取り込みは 2 段階あります。

```
0x008EB2   ステージ 1   メインループの末尾
0x014E7A   ステージ 2   move.w D2, ($b94,A5)   ここで $B94 が埋まる
0x02211A   消費         ゲームロジックが読む
```

**ステージ 1 はメインループの末尾**にあります。FBNeo のパッドに値を置いても、
ゲームがそれを見るのは**次のティック**です。しかも Lua の `joypad.set()` は
表示フレームに 1 回しか回りません。

つまり「今のティックで判断して、今のティックの入力にする」ことがパッドでは
できません。**判断とその結果の入力が同じティックに入らない**わけです。

### 書く場所と書き方

**消費の直前(`0x02211A`)にフックを置き、そこで直接書きます。**
ゲームがこれから読むコピーに書き込むので、その場で効きます。

```
0xFF8B94   ボタン    ( P1 は 0xFF8794 )
0xFF8B95   レバー
```

守ることが 2 つあります。

**1. 両方のバイトを毎回書く。**レバーのバイト(`0xFF8B95`)だけを書いても
**入りません。**実測では、保持中にレバーだけ書いたフレームは `$123` が `0x00`
のままでした。届いたのは `0xFF8B94` も書いたフレームだけです。ボタンが無い
ときも 0 を OR して両方書きます。仕上げにゲーム自身と同じ形
(`move.w`、`0x014E7A` と同じ)でワード書き込みをもう一度行います。

**2. レバーは OR ではなく代入。**保持中の値に OR すると、残っていた下と
新しい後ろが合わさって**下後ろ**になります。回転系の認識(`0x02A1B4`)は
4 方向と `cmpi` で完全一致を取るので、斜めは弾かれます。エントリが持っている
ビットこそが押すべきものなので、そのまま代入します。

### レバーのビット

**向きによって前後が入れ替わります。**`$0B` が向きです。

```
向き 0    前 = 0x02   後 = 0x01
向き 1    前 = 0x01   後 = 0x02
共通      下 = 0x04   上 = 0x08
```

ゲーム側も `0x022194` で `$122` の bit0 と bit1 を交換しています
(交換表は `0x0221C8`)。**方向は必ず注入する瞬間の向きで解決してください。**
モーションの途中で振り向くキャラがいるので、キューに積む時点でビットに
変換すると左右が逆になります。

### パッド経由の入力との共存

`joypad.set()` は同じ入力を 1 ティック遅れで届け続けますが、害はありません。
**ゲームは先に注入した値を見て、その後にパッドの値を見る**ので、
「押した → 押しっぱなし」と読まれ、**エッジは注入したティックに立ちます。**

### 押しエッジ

```
$126 = ~$124 & $122      新しく押されたビット
```

**握りっぱなしの方向は、もう一度入れてもエッジになりません。**
ダミーがガードのためにレバーを後ろに握っている状態で「後ろ」を入れても
`$126` は立ちません。**一度中立に戻してから入れ直す**必要があります。
後ろダッシュがそのままでは出ないのはこれが理由です。

## 5. 「動ける 1 ティック前」を知る

やられ・ガード・ダウンから復帰する **1 ティック前**に、ゲームが必ずこれを書きます。

```
024F0A: 2D7C 0202 0400 0004   move.l #$2020400, ($4,A6)
```

つまり `$04=02 $05=02 $06=04 $07=00`。**この直後のティックでキャラは動けます。**
14 キャラ中 13 キャラで 250 回中 249 回。

Q-Bee だけは別のハンドラ(`0x04A6FA`)を通り、この署名を出さずに
`0x04A7A0` から抜けます。個別扱いが必要です。

この署名が出る条件は 1 つ手前にあります。

```
024F02: 4A2E 0021             tst.b  ($21,A6)      ; 最終セルか
024F06: 6A00 3068             bpl    $27f70        ; 違えば $20 を減らすだけ
```

`$21` は最終セルの持続が尽きたときに `0x027F88` で `0xFF` になります。

### 行動が出せる最速ティック

```
必殺技コマンド(波動・昇龍・半回転・1 回転…)   押しは free-1、行動は free+0
それ以外(ダッシュ・通常技・投げ・ジャンプ・DF)  押しは free+0、行動は free+1
```

**非必殺技は 1 ティックずれると「遅れて出る」のではなく「出ません」。**
ダッシュの 2 回目のタップを free+1 に置くと `$06` が `0x14` にならず、
代わりに通常技が出ます。

## 6. 起き上がり

`$1A7` が起き上がり中に 1 ティックずつ増えます(`0x024E84`、`$194` と `$15D` で門番)。
終端値はアニメーションの長さで、**アニメ 44 の持続合計 + 2**(9 キャラ中 8 キャラで一致)。

終端値はキャラと `$07` で決まります。実測値:

```
キャラ         $07=2/4   $07=6
ガロン           29        31
ビクトル         30        30
ザベル           22        38
モリガン         27        47
アナカリス       27        46
ビシャモン       23        30
オルバス         28        33
サスカッチ       23        47
レイレイ         29        30
リリス           27        47
ジェダ           24        39
```

Q-Bee は `$1A7` ではなく **`$0A` の符号**で決まります(0 → 15、負 → 40、正 → 47)。
デミトリはアニメーションで終わらず着地判定を待つため、`$1A7` では計れません。

## 7. ガードとガードキャンセル

```
02395A: move.b #$2, ($140,A6)    ; 地上ガード
023960: move.b #$e, ($158,A6)    ; ガードキャンセル受付 14
023966: move.b #$e, ($1ab,A6)    ; プッシュブロック受付 14
022492: subq.b #1, ($158,A6)     ; 毎ティック
02249C: subq.b #1, ($1ab,A6)     ; 毎ティック
```

`$158` は**ガードキャンセルの窓であって、硬直の長さではありません。**

### 硬直の長さを決めているもの

ガード硬直に**カウンタは存在しません**。ディスパッチャは 0x024A22 で、
`$07` をサブステップとする語テーブルで飛びます。毎ティック走るのは
`$07 = 2` の枝で、`bsr $27DE4` が真を返した瞬間にガードが終わります。

```
027DEA: move.b ($59,A6), D0     ; 攻撃側の食らいデータ(0x0764EA+5)が決める反応タイプ
027DF0: lea    ($285de,PC), A0  ; タイプ別スクリプトの語オフセット表(符号付き、自己相対)
027DF8: lea    (A0,D0.w), A0
027DFC: move.w ($164,A6), D0    ; カーソル
027E00: move.b (A0,D0.w), D0    ; 1ティック 1バイト
027E04: bmi    $27e2a           ; 負 = 終端 → ガード終了
027E06: addq.w #1, ($164,A6)
027E22: add.w  D0, ($10,A6)     ; 負でなければ、そのティックの X 押し戻し量
```

**押し戻しの距離と硬直の長さは同一のデータです。**バイトが尽きたら硬直が
明けます。表は 0x0285DE。**データ領域なので MAME のリスティングでは読めず**
(CPS2 は命令フェッチしか復号しない)、実機から読む必要があります。

| `$59` | 長さ | 押し戻し |
|---|---|---|
| 0 (弱) | 11 | `04 04 04 04 03 03 03 02 01 01 01` |
| 1 (中) | 16 | `03 04 04 04 05 06 06 05 04 03 02 01 01 01 01 01` |
| 2 (強) | 20 | `04 05 06 07 08 08 08 07 06 05 04 03 02 01 01 01 01 01 01 01` |
| 3 | 24 | `0a` ×8 から `01` まで |
| 4 | 48 | 全部 `00` (押し戻し無し) |
| 7 | 20 | `0c 0e 10 10 10 10 08 08 …` (頭が重い) |
| 8 | 16 | `04 03 02 01` のあと `00` ×12 |
| 9 | 36 | |

### `$158` を硬直の基準に使ってはいけない理由

`$158` は接触時に 14 が入り、0x022492 が**毎ティック**減らします。対して
`$164` は**キャラが実際に動いたティックしか進みません**。つまりヒットストップ
中は `$158` だけが減り、スクリプトは止まったままです。

デミトリのゼロデモンは `$164` を **12 ティック 0 のまま**保持します。その間に
`$158` は 14 から 2 まで燃えてしまうので、`$158` を基準にした予測は free を
追い越します。保存した 710 本のガードを再生すると、強のガード 229 本のうち
**111 本 (48%)** で予測が free 以降に落ちていました。

**ガードされたゼロデモンの硬直は 20 ティックで、普通の強と同じです。**
硬直が短かったのではなく、基準にしていた時計が別物だった、というだけです。

残りティックは `長さ − $164` で毎ティック正確に取れます。

### 近接ガード(影縫い)

後ろを入れたときにガードポーズを取って動けなくなるかどうかは、ゲーム自身が
決めています。入口は 0x02766A / 0x027688、返り値 D0 = 1 で成立。二段構えです。

**前半 0x0276AC — オブジェクト走査。** `A5+0x1400` (= 0xFF9400) から 0x100
刻みで 32 個。生きていて(`(A4)==1`, `$01!=0`, `$a2==0`)、自分の持ち物でなく
(`$70` が自分と違う)、現セル `$1c` の `$17` の bit7 が落ちているオブジェクトが
一つでもあれば成立します。**距離を見ません** — 飛び道具が画面のどこにあっても
後ろに下がれないのはこれです。

**後半 0x0276DE — 相手プレイヤー。** `$154` が非0なら無条件成立。`$105` が
0 なら不成立。そうでなければ `$8c` の技ごとの判定枠テーブルを引きます。

```
027712: movea.l ($8c,A4), A1     ; 判定枠テーブル
027716: move.b ($a,A0), D0       ; セルの枠 index
02771C: ext.w / lsl.w #5         ; *32
027724: move.w (A1), D0          ; 枠のオフセット(向きで符号反転)
02772E: add.w  ($10,A4), D0      ; 枠の X
027732: sub.w  ($10,A6), D0      ; 自分との距離
02773A: move.w ($4,A1), D1 / addi.w #$80, D1
027742: cmp.w  D1, D0 / bhi 次のセル / 成立
027754: lea ($18,A0), A0         ; 残りのセルを先読みする
```

**技ごとに影縫い距離が決まる**のはこの枠データです。その外では後ろを入れても
ガードポーズにならず、ただ歩きます。通常技は持続が短いので歩きが見えません
が、持続の長い必殺技(デミトリのデモンクレイドル等)でははっきり歩きます。

`$ac` (0x0276F8) は **無条件成立ではありません**。`$38` による却下を飛ばして
範囲判定の途中に入るだけです。

## 8. プッシュブロック

**約 12 ティックの窓の中で、押した回数**を数える仕様です。

```
0275D8: tst.b  ($1ab,A6)          ; 窓が閉じたら拒否
0275E0: tst.b  ($184,A6) / bne    ; 既に成立していたら拒否
0275E8: cmpi.w #$202, ($4,A6)     ; $04$05 が 02 02
0275F0: cmpi.b #$2, ($140,A6)     ; 地上ガード
0275FE: bsr    $274ba             ; $126 & $77 = このティックの押し
027606: addq.b #1, ($170,A6)      ; 回数を積む
02760E: cmpi.b #$8, D0 / bcc      ; 8 回以上は無条件で成立
027616: lea    ($28d50,PC), A0    ; 8 未満は回数別の確率表
02761E: jsr    $14e8a.l           ; 乱数
027632: move.b #$1, ($184,A6)     ; 成立
```

* 押しは **6 ボタンのどれでもよく、1 ティックにつき 1 回**(`$126 & $77`)。
* 成立した瞬間に `$184` が立ち、**以降の押しは数えられません。**
  `$170` が途中で止まるのは取りこぼしではなく成立です。
* 8 未満の確率表(`0x28D50`)は思ったより甘く、3 回で成立することが普通にあります。

### 成立すると硬直の時計が変わる

**ガード硬直とは別経路になります。**7 章のディスパッチャ(0x024A22)は `$07` で
枝を選びますが、成立するとその `$07` が書き換わります。

```
024A66: tst.b  ($184,A6)          ; 成立していたら
024A6C: move.b #$6, ($7,A6)       ;   サブステップを 6 へ
024A72: move.b #$a, ($26,A6)      ;   $26 = 10
...
024AFC: subq.b #1, ($26,A6)       ; $07 = 6 の枝は毎ティックこれ
024B00: bne    $24b22
024B02: move.l #$2020400, ($4,A6) ; 通常ガードと同じ free 署名
```

**ガードスクリプト(`長さ − $164`)は捨てられます。**成立後の残りティック数は
**`$26` そのもの**です。10 から始まるので、free の 9 ティック前を狙うなら
`$26 <= 9` で掛かります。

プッシュブロック後の最速行動を出すには、`$07 == 6` を見て時計を `$26` に
切り替える必要があります。ここを取り違えると「プッシュブロックは出るが
最速行動が出ない」になります。

## 9. コマンド認識

* 入口は `0x029F4A`。読むのは **`$12A`**。
* `andi.w #$f` でボタンは無視。`cmp.w` の完全一致(bit7 が立っている場合を除く)。
* **毎ティック比較され、中立のティックで進行がクリアされます**(`clr.b (A4)`)。
* ステップのタイムアウト表は `0x02A55A`、値は 14〜19 ティック。
  **完成したコマンドはこの長さだけ保持されます。**

## 10. アニメーション

```
0x0BCF7A   キャラ別のアニメーションテーブル(long)
```

そこから**ワード単位のオフセット**でアニメ ID を引きます。セルは **24 バイト**。

```
+0x00  持続ティック
+0x01  フラグ  bit6 = 最終セル(st ($21,A6))
                bit7 = +0x18 のポインタへジャンプ
+0x18  ジャンプ先
```

ステッパは `0x027F70`。`$20` を毎ティック減らし、0 になったら次のセルを読みます。

## 11. ダッシュ

`$06 = 0x14` がダッシュ状態そのものです。**ダッシュ攻撃はダッシュ状態の中の
ジャンプ技なので、`$06` は `0x14` のまま変わりません。**攻撃が出たかどうかは
`$105`(攻撃フラグ)で見ます。

```
027982: move.l #$2001400, ($4,A6)   ; ダッシュ状態へ
```

* ダッシュは **タップ → 中立 → タップ**。2 回目のタップは **free+0** でなければ成立しません。
* 1 回目のタップは位置に余裕があります。実測で **free−10 まで**成立します。
* **中断は逆方向。**認識するタイミングは 1F のみですが、押しっぱなしで問題ありません
  (攻略 wiki サスカッチ)。
* **デミトリは中断不可**(攻略 wiki 基本動作)。
* ザベルはダッシュが攻撃フラグを立てるため、ダッシュ攻撃の差分が常に 0 になります。

## 12. ステージの座標とカメラ

`$10` は世界座標の X(16.16 の上位語)です。

### 書いた位置は補正されません

外から `$10` に書いた値は**ゲームに補正されません。**壁を越えて書けばキャラは
ステージ外へ出て画面から消えます。移動させるときは自前でクランプが要ります。

### キャラはカメラの枠に閉じ込められています

ゲームは 2 人を画面内に保つため、**片方が右にいると相手はそれ以上左へ行けません。**
その結果:

* **キャラ単独ではステージ端に到達できません。**壁を測るには 2 人とも同じ隅へ
  追い込む必要があります。
* 枠外へテレポートさせると**画面端まで引き戻されます。**カメラは自分から
  追いつきません。

### 壁は全ステージ共通

2 ステージで実測して同じ値でした。**ステージ別のテーブルは要りません。**

```
左壁 280    右壁 1000    幅 720
```

ラウンド開始位置は `554 / 728`(間隔 174)。その中点 641 は、壁から出る中央 640
と一致します(独立した 2 つの測定が揃っています)。

### スクロールは出力であって操作点ではありません

`0xFFB810` / `0xFFB890` / `0xFFB910` / `0xFFB990`(0x80 刻み)は歩きに追従して
動く 4 つの語ですが、**書き込んでも少ししか動きません。**ゲームがキャラの実位置
から計算し直すためです。

**位置を変えるなら、飛ばさずに少しずつ動かします。**毎フレーム 12px ずつなら
歩いているのと同じ状況になり、カメラは自分で追いつきます。

## 13. CPS2 の注意

**`mame_code` などの逆アセンブル結果は命令空間のものです。**CPS2 は命令フェッチ
のみ復号されるため、**データテーブルは逆アセンブル上ではゴミになります。**
`0x28D50` のような表の中身は、実機のメモリから読む必要があります。

判断材料にする前に、必ずどちらの空間の話か確認してください。
