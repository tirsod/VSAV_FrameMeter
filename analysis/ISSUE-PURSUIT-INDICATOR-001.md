# ISSUE-PURSUIT-INDICATOR-001: Show Pursuit Indicator の 3 行が互いに矛盾している

**状態: 未修正。直さないと決定 (2026-09-13)。**
本人の判断で「さほど欲しい機能ではないので、あまり変えなくてよい」。
v11.7 のメニュー再編では Analysis タブへそのまま移しただけで、中身は触っていない。

コードを読んだだけの結果であり、**エミュレータでの実測はしていない。**

---

## 症状

**3 行のうち 2 行は、どの設定でも描かれない。**

`timers.lua` の描画は 3 つに分かれていて、うち 2 つは
`globals.options.show_ground_special` で守られている。ところがこのキーは

- `config.lua` に既定値が無い
- `menu.lua` に行が無い

ため、常に `nil` になる。つまり `Show Pursuit Indicator` を ON にしても
出るのは `Opponent OK` の 1 行だけで、`Player OK` と `Pursuit OK` は
**一度も描かれたことがない。**

## コードから確定していること

| 描画関数 | 読む値 | ラベル | 座標 |
|---|---|---|---|
| `draw_pursuit_timer(1, …)` | **P1** の `p1_can_pursuit` | `Opponent OK` | 23,119 |
| `draw_ground_special(1, …)` | **P1** の `p1_ground_special` | `Player   OK` | 23,111 |
| `draw_pursuit_OK()` | `globals.controlling_p1` で選んだ側 | `Pursuit  OK` | 23,127 |

1. **上 2 行は同じ P1 を「Opponent」と「Player」という別名で呼んでいる。**
   さらに `dummyState.lua` の `get_pursuit_ok()` はこの 2 つを AND している。
   AND する以上は同一人物のはずなので、**どちらかのラベルが誤っている。**
2. **上 2 行は P1 固定、3 行目だけ操作側に追従する。**
   2P 側を操作すると、3 行が別々の人物を指す。
3. 直前の追い討ち長を出す行の座標が **P1 は `(72,127)`、P2 は `(72,27)`** と
   100px 離れている (`timers.lua:299` / `timers.lua:305`)。片方は位置が誤り。
   なお、すぐ下にある同じ描画のブロックはコメントアウト済みで、生きているのは
   この 2 行だけ。
4. その行の単位が **`"F"`** になっている。ツールが測る値はすべてティックに
   統一してあるので、ここも `Tick` のはず。ただし `playerObject.lua` が
   何で数えているかは未確認。

## 確定していないこと

**`can_pursuit` が「追い討ちできる側」なのか「追い討ちされる側」なのかが未確定。**
これが決まらないとラベルのどちらを直すべきかが決まらない。

0x27B14   フラグを立てる側
