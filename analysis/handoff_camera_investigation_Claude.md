# Claude引き継ぎ: VSAVカメラ拘束と瞬間移動の調査

## 目的
`position.lua` は現在、Hotkey 2とレバー方向の組み合わせで両キャラクターを毎表示フレーム12pxずつ滑走させ、カメラを追従させる。最終目的は、左端から右端などへ一度に配置してもカメラ枠に阻まれないよう、ゲームが使う主カメラ値、境界値、更新PCを確定すること。現段階では瞬間移動ロジックを実装せず、観測だけを行う。

## 確定事項
- P1/P2オブジェクトは `0xFF8400` / `0xFF8800`。世界Xは各 `+0x10` の上位word。
- `0xFFB810`, `0xFFB890`, `0xFFB910`, `0xFFB990` は0x80間隔で、歩行に追従するが直接書いても再計算される。主操作点ではなく出力側。
- 同梱のCPS2 hitbox viewerはVSAV系プロファイルで `0xFF8290` を `left_screen_edge` として参照している。最優先候補。
- 静的逆アセンブル `0x008414-0x008438` はA5相対 `$028C/$02AC/$02C4/$02CC` に目標追従型の計算を行う。ただし通常対戦カメラか画面演出用かは未確定。

## 静的解析で確認した式
```asm
008414 move.l ($028C,A5),D0
008418 cmp.l  ($02AC,A5),D0
00841E move.l ($02C4,A5),D0
008422 sub.l  ($02CC,A5),D0
008428 move.l ($02C4,A5),D0
00842C add.l  ($02CC,A5),D0
008430 add.l  D0,($02AC,A5)
008434 move.l D0,($02C4,A5)
```
A5=`0xFF8000`なら候補は `FF828C/FF82AC/FF82C4/FF82CC`。ただし `$028C` は `0x006ED0` で `0x00010000` に初期化されるため、世界Xと即断しないこと。

## 今回の変更
### `scripts/position.lua`
既存のHotkey 2 + レバーによる滑走だけを識別する完了シリアルを追加した。
- `hotkey_move_active`
- `hotkey_move_completed_serial`
- 公開関数 `positionModule.hotkey_move_completed_serial()`

メニューのStage Position変更ではシリアルを進めない。既存の配置、速度、入力マスク、Hotkey 2の挙動は変更していない。

### `scripts/cameraProbe.lua`
観測専用。プレイヤー、カメラ、ROMへは書き込まない。
1. Hotkey 2 + レバーの滑走完了を待つ。
2. 完了から約120表示フレーム待つ。120は安定待ちの概数で、内部tick精度は求めない。
3. 自動的にCSV記録を開始。
4. 1800表示フレーム、試合終了、または次のHotkey 2移動で停止。
5. 次のHotkey 2移動が完了すれば、再び120フレーム後に新しいCSVを開始できる。

画面表示:
- 待機中: `CAM PROBE WAIT <残り概数>`
- 記録中: `CAM PROBE REC`

出力先:
- 通常 `reversal_logs/camera_probe_<frame>.csv`
- 開けない場合 `scripts/camera_probe_<frame>.csv`

監視値:
- P1/P2 X: `FF8410`, `FF8810`
- 候補: `FF828C`, `FF8290`, `FF82AC`, `FF82C4`, `FF82CC`
- 出力: `FFB810`, `FFB890`, `FFB910`, `FFB990`

WRITE行は書込時の68000 `PC/A5/A6/D0/D1/D2` を保存する。SAMPLE行は1表示フレームにつき1行に全候補値をまとめ、低負荷化している。write hookのコールバックが書込前か後かは実ログで確認し、旧値なら次のSAMPLEと組み合わせて読む。

## 実機テスト
1. Fightcade/FBNeoを完全終了し、この版で再起動。ROMリセットだけではLuaを再読込しない。
2. ラウンド開始後、Hotkey 2を押しながら任意のレバー方向を入れ、既存の高速滑走を実行する。
3. 滑走完了後、画面左上に `CAM PROBE WAIT` が出ることを確認する。
4. 約120表示フレーム後、`CAM PROBE REC` へ変わることを確認する。
5. 記録中に通常歩行、両者の位置変更、画面端付近の移動など再現したい操作を行う。
6. 1800表示フレーム待つか、試合を抜ける。別方向のHotkey 2移動を行うと現在ログを閉じ、移動完了後に次ログを開始する。
7. CSVを回収する。

## 解析手順
1. `FF8290` とP1/P2 Xを比較する。画面左端なら `screen_x = world_x - FF8290` が概ね安定するはず。
2. WRITE行をアドレス別、PC別に集計する。
3. `FF8290` writerを逆アセンブルへ戻し、元値、クランプ、画面幅定数を追う。
4. スクロール4値のwriterとの合流点を探す。
5. `FF828C/FF82AC` は歩行方向との相関、画面端での停止、通常ラウンド中の継続変化を確認する。演出時のみなら候補から外す。
6. 主値確定後にだけ、別コピーでP1/P2 Xとcamera current/target/previousを同一delta更新する実験へ進む。

## 競合と注意
- Hotkeyは追加していない。既存Hotkey 2をそのまま使う。
- `position.lua`の既存12px滑走を維持している。
- 常時NOP、ROMパッチ、カメラ拘束の恒久無効化は行っていない。
- 候補アドレスについて、添付版内に既存の`memory.registerwrite`登録は見つからなかった。
- write hookは停止中も登録自体は残るが、先頭で`active`を検査し、記録処理を行わない。
- CPS2のmame_codeは復号命令空間。データテーブルを逆アセンブル表示だけで解釈しない。
