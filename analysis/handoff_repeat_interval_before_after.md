# 引き継ぎ: リピート再生インターバル Before / After

## 対象
VSAV Training v11.4.1 系。変更対象は `scripts/menu.lua`、`scripts/macro.lua`、`scripts/config.lua`、`scripts/utilities.lua`、`scripts/training_settings.json`、日英リリースノート。

## 実装済み要件

### 1. インターバルを前後へ分割
設定キーを次の2つへ変更した。

- `loop_interval_before_frames`
- `loop_interval_after_frames`

親メニューの表示は `Loop Interval (Frames) : (Before/After)  >`。たとえばBefore=10、After=20なら `(10/20)` と表示する。

### 2. 右入力で子階層へ入るUI
親項目の末尾に `>` を表示し、右またはLPでポップアップを開く。右は「さらに深い階層へ入る」というメニュー全体の意味に合わせた。

子ポップアップには次の2行がある。

- `Before`
- `After`

値の範囲は各0から300フレーム。

### 3. 左入力で親階層へ戻る
子ポップアップ内の操作は以下。

- 上下: Before / After選択
- 左: 親階層へ戻る
- 右: 値を1増加
- LP: 値を1減少
- MP: 0へリセット

左を数値減少に使わず、階層を戻る操作へ統一した。

### 4. Before / Afterの実行順序
通常の距離復元時:

1. 前回再生終了
2. P2が行動可能になるまで待機
3. After待機
4. `Reset Distance Each Loop`による録画時距離への復元
5. Before待機
6. 次回再生開始

Before=10なら、ワープ後に10表示フレーム停止してから再生する。

録画セーブステート使用時:

1. 前回再生終了
2. P2が行動可能になるまで待機
3. After待機
4. 録画セーブステートをロード
5. Before待機
6. 次回再生開始

Before/Afterが0なら、その段階の余分な待機はない。

### 5. メニュー終了後30表示フレーム停止
トレーニングメニューが開状態から閉状態へ変化したフレームを検出し、30表示フレームのホールドを開始する。

対象はリピート再生のみ。単発再生へ副作用を広げない。

ホールド中は以下を停止する。

- 次のループ開始
- 再生中ループのフレーム進行
- 録画入力の出力
- Before / Afterカウント
- 距離復元
- セーブステートロード

`emu.framecount()`の期限方式を使い、`registerBefore`が同じ表示フレームに複数回呼ばれても30Fが短縮されない。閉じたフレームを含む30フレームは停止し、期限到達時に同じ録画位置から再開する。

### 6. 旧設定の移行
旧キー `loop_interval_frames` を持つ設定は、`settings_version < 3` の一回限りの移行で以下へ変換する。

- Before = 0
- After = 旧 `loop_interval_frames`

旧実装の待機位置に近いAfterへ移すことで、ユーザーの保存値を失わない。移行後は旧キーを削除し、`settings_version = 3` とする。

## 主な実装箇所

### `scripts/menu.lua`
- `interval_popup_menu_item()`を追加
- 親表示 `(Before/After) >`
- `make_popup()`を使う子階層
- 左で閉じる、右で増加、LPで減少、MPでリセット

### `scripts/macro.lua`
- `loop_phase = "after" | "before"`
- After終了後に距離復元またはステートロード
- その後Beforeを待って再生
- `update_loop_menu_hold()`でメニュー閉鎖エッジを検出
- `loop_menu_hold_active()`でリピート再生だけ30F停止
- 待機中は`get_keytable()`が空入力を返す

### `scripts/utilities.lua`
- 設定バージョン3への旧インターバル移行

## 批判的レビューで発見し修正した事項

1. **旧保存値が失われる問題**
   - 新しいデフォルト値が先に存在するため、単純なnil判定では旧値を拾えない。
   - JSONから読んだ生テーブル `_training_settings.loop_interval_frames` を参照してAfterへ移行するよう修正。

2. **30F停止が単発再生にも作用する問題**
   - 初稿は`playing`全体を止めていた。
   - `loop_pending`、`loopmode`、`looped_playback`のいずれかである場合だけ停止するよう限定。

3. **再生フレームだけ止めても直前入力が残る問題**
   - `get_keytable()`もホールド中は空テーブルを返し、録画入力が漏れないよう修正。

4. **同一表示フレームの複数コールバック問題**
   - デクリメント方式を避け、`emu.framecount() + 30` の期限方式を採用。

5. **Beforeの実行位置**
   - 距離復元またはステートロード後に`loop_phase="before"`へ遷移するため、ワープ後停止という要件を満たす。

## 実機確認項目

1. 親表示が `(10/20)  >` になる。
2. 右またはLPでポップアップが開く。
3. 子階層で左を押すと親へ戻る。
4. 子階層で右増加、LP減少、MPリセットが動く。
5. Reset Distance Each Loop有効時、Before=10でワープ後10F停止する。
6. After=20で回復後、ワープ前に20F待つ。
7. メニューを閉じた直後、ループ再生中でも30表示フレーム動かず、その後同じ録画位置から再開する。
8. 単発再生には30F停止が適用されない。
9. 旧設定ファイルの単一インターバル値がAfterへ移行する。
10. 設定保存後、再起動してBefore/Afterが維持される。

## 未検証
FBNeo実機での表示幅、ポップアップ位置、入力同時押し、セーブステートロード直後の見た目は、この環境では実行確認できない。静的整合性とZIP破損検査を行ったうえで実機確認すること。

## 取り込み時の変更 (こちらの環境)

受領後に次を変更した。資料本文の記述より、こちらが現在の実装である。

### 子階層の操作をレバー完結に変更

| 入力 | 変更前 | 現在 |
|---|---|---|
| 左 | 親階層へ戻る | 値を1減少 |
| 右 | 値を1増加 | 値を1増加(変更なし) |
| LP | 値を1減少 | Back行でのみ決定 |
| MP | 0へリセット | 0へリセット(変更なし) |

「戻る」は方向ではなく `Back` 行として持たせ、**行の一番下**に置いた。理由は次の2点。

- レコーディングウィザードのスロット選択が既に一番下に「メニューにもどる」を置いており、ツール内で位置が揃う
- ポップアップを開いた直後のカーソルが `Before` に乗るので、開いてすぐ値を操作できる

`Back` 行に右は割り当てていない。右はオートリピートし、親行は右で開き直すため、押しっぱなしで閉じると次のリピートで再び開いてしまう。右の意味を「奥へ、または増加」に統一する意図もある。

ポップアップの箱は3行に合わせて `bottom` を 132 から 140 へ広げた。

### 批判的レビューで発見し修正した事項

1. **v11.3.x からの設定移行が飛ぶ**
   `config.lua` の既定値を `settings_version = 3` にしたため、`settings_version` を持たない古いファイルが既定値の3を読み、移行が全て skip される。counter_attack_stick が黙ってズレ、旧インターバル値も失われる。移行の判定を、マージ後ではなく生のファイルテーブルが名乗ったバージョンから取るよう修正。

2. **右で開くとそのまま Before が増える**
   右はオートリピート(4フレーム間隔)なので、押しっぱなしで開くと次の発火が子の行に届く。開いた直後15フレームは子の右加算を無視するよう修正。

3. **`Play Recording` の15フレームデバウンスが元々無効**
   `frame_number` は inputHistory.lua のファイルローカルで、menu.lua からは常に nil。`last_fired` が nil になり条件が永久に偽。`emu.framecount()` へ置換。

4. **30F ホールド明けに録画が早送りされうる**
   進行を止めるだけでは `emu.framecount()` が進み続け、`framecount - frame >= framediff` が複数回満たされる。ホールド中は毎フレーム `framediff` を張り直し、`frame == framecount - framediff` を維持するよう修正。

5. **ポップアップがメニューを閉じても残る**
   `togglemenu()` で `current_popup = nil` を追加。

6. **コメントの誇張**
   「Before の間は両キャラが停止したまま」は誤り。止まるのは再生であってキャラではなく、ダミーに行動を設定していれば Before 中も動く。実態に合わせた。
