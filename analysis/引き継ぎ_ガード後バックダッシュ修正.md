## 修正内容
`VsavPrj/fightcade/emulator/fbneo/scripts/guardCancel.lua` の2箇所を正本 `C:\fightcade\emulator\fbneo\scripts\guardCancel.lua` へ反映

### 1. `guardCancel.lua:4994` BLK_ARM_LEADの強度別化
```lua
local BLK_ARM_LEAD = 9
local _arm_lead = BLK_ARM_LEAD
local _s59arm = memory.readbyte(0xFF8859)
if _s59arm == 0 or _s59arm == 1 then _arm_lead = 12 end
```
- 従来は全強度で9tick。Light(gsl11)とMedium(gsl16)は12tickでないとフレームサンプリング(1.6tick/frame)でarmが遅れてタップ6tick分が不足し、Mediumで20%しか出なかった。Heavy(gsl20)は12で0%に悪化するため9のまま。

### 2. `guardCancel.lua:5035` 入力ベースのneutral注入
```lua
BLK.lg = memory.readbyte(0xFF8081)
BLK.neutral = 3
```
と
```lua
if _s0 ~= nil and _s0.blk_hold and ... and is_plain_dash() then
    if BLK.neutral and BLK.neutral > 0 then
        assert_input_bits(0, 0)
        BLK.neutral = BLK.neutral - 1
        debugKnockdownModule.mark_write("blk_neutral", BLK.neutral, memory.readbyte(0xFF8081))
        return
    end
```
- 従来のHeavy用 `memory.writebyte(0xFF8913/14/0xFF8A43/0xFF8A08/0xFF8A3A)` によるダッシュ認識クリアはチート寄りのため除去。
- 代わりにarm後3tick `0xFF8B94($394)` に `neutral` を生入力で注入し、認識器を自然にリセット。正道方式(タイミングはメモリから読み取り、操作は生入力)。

### 検証方法
- 生入力 `0xFF8B94` でタイミングを合わせて操作する方式を維持。`0xFF8913`等への直接writeは不使用。
- 成功判定は `a 0x02->0x00` かつ `r=2(ガード)` でのfree遷移後12tick以内に `$06==0x14` (ダッシュ) が立つか。`dash_delay.py` および `explain_leads.canonical` で集計。
