### 解決済み(2026-08-26)

Stage A はスロット選択 → 録画開始 → 120F 自動完了 → 保存まで通しで動作確認済み。
以下 3 件はいずれも修正済み。

1. **録画が始まらない(必ず arm_timeout)** — 原因は ARMED の開始条件が
   成立しないこと。`arm_settled` が入力のあるフレームで毎回 false に落とされ、
   その直後の判定が「`arm_settled` が真かつ入力あり」を要求していたため、
   入力があれば直前に false、入力がなければ開始する入力がない、という
   どちらでも成立しない状態だった。最初のニュートラルフレームでラッチして
   以後下ろさない形に変更。ラッチの目的はスロット選択の LP を最初の録画入力と
   誤認しないことだけ。
2. **入力判定のソース違い** — `p2_has_valid_input()` が
   `player_objects[2].input` を見ていた。`controller.registerBefore` は
   `globals._input` の中で P1↔P2 をスワップする(`controller.lua:945`)が、
   `playerObject.update_input` が `joypad.get()` を取り直す
   (`playerObject.lua:81`)ため生ポートに戻る。操作を P2 に切り替えると
   アケコンは物理 P1 なので、`player_objects[2]` には現れない。
   判定を `globals._input` に統一した。1 とは独立した別の不具合。
3. **確定時に Lua エラー** — `macro.lua` の末尾ニュートラルトリムが
   `next(fr[p])` でフレーム項目をテーブル扱いしていたが、`registerAfter` は
   `key.symbol` を連結した文字列として積む。空文字列比較に変更。

**録画トラックは P2 で正しい**(未解決だった「1P 側に記録されるように見える」は
録画開始まで到達していなかった時点の観察)。`wizard_temp.mis` の実測:
P1 は `W56`(待機のみ)、P2 に入力列。P1 の空トラックは再生に影響しない —
`keytable` は押されているキーだけを書き、`false` を入れない
(`macro.lua:1024`)。

### 現在のシーケンス(2026-08-26 時点)

```
IDLE → メニュー Recording タブ →「Recording Wizard」を LP
SELECT_SLOT   上下でスロット 1-5 / LP 決定 / MP 取消
ARMED         操作を P2 へ。P1/P2 の X 座標を保存。30F ウェイト後、
              ニュートラル 1F でラッチ
RECORDING     最初の入力から記録。60F ニュートラルで自動完了
FINALIZING    末尾トリムして wizard_temp.mis へ。操作を P1 に戻し、
              位置を復元
PREVIEW       wizard_temp.mis を P2 で 1 回再生(ユーザは P1 で観る)
CONFIRM       LP: 保存 / MP: 録り直し(ARMED へ) / LK: もう一度再生
IDLE          結果を 3 秒表示
```

- スロット一覧は Saved ではなく撮影日時を出す(.mis ヘッダから。開いた
  ときに一度だけ読む)。
- 全状態で Lua key 1 がキャンセル(= 破棄)。ホットキーはフラグを立てる
  だけ。過去にコールバック内で処理を書いてホットキーを壊した経緯がある。
- パッド遮断は SELECT_SLOT / ARMED(ラッチ前) / CONFIRM。加えて、確認に
  答えたボタンが離されるまで遮断を続けるラッチがある(答えた次のフレーム
  には別状態に移っていて遮断が外れ、押しっぱなしの分がゲームに届いて
  いた)。PREVIEW は開けてあるので、再生をガードして確認できる。
- **遮断は macro のキーマージより前で行う**(master)。後ろだと P2 を
  塞いだ時点で再生キーごと消えるため、P1 しか塞げない。
- ウィザード中は自前のプレビュー以外の再生を毎フレーム停止する。再生
  ホットキーはウィザード中も生きているため。
- 再生はループ設定を一時的に無効化する(ループのままだと終わらない)。

### 向きと再生 (2026-08-26)

- 録画開始時に向きバイト 0xFF880B を採取し、finalize が
  `# p2facing <n>` としてヘッダに書く。通常録画とウィザードの両方。
- 再生時は現在の向きと記録された向きを比較して左右を反転する。値を持た
  ない旧ファイルは「P2 が右で録る」という従来の前提にフォールバック。
- 反転は master の `merge_macro_keys` に集約。ウィザードのプレビューだけ
  は自分が保存した向きと比較する。

### ループ再生 (2026-08-26)

- 従来はマクロ終了の次フレームで無条件に再開していた。末尾ニュートラルを
  落としてあるので前の技の硬直中に次の周が始まり、free+0 に乗らない入力は
  出ていなかった。
- `$05`(0xFF8805) と `$06`(0xFF8806) が両方 0 になるまで再開を保留する。
  300 フレームのタイムアウトを backstop に置いてある。
- `use_recording_savestate` が ON のときは従来どおり即再開(ロードで状態
  ごと戻るため)。

### 未解決(この続きから)

1. セーブステート連携(録画開始時に取得し、再生前に読み込む)は未実装。
   `use_recording_savestate` の既存機構と揃えるか要検討。
2. ARMED / RECORDING 画面の `Ready :` `Held :` はデバッグ表示。外すか判断。
3. ループ再開の判定 `$06 == 0` は立ちニュートラル。しゃがみや歩行から
   再開しない。実運用で遅い/かからない場合は「行動可能なグループ」へ
   広げる。
4. 既存スロットの上書き警告は「Overwrites the recording from <日時>」の
   一文のみ。二段確認が要るかはユーザ判断。

## ランチャ(最終形)

`C:\fightcade\emulator\fbneo\run_vsav_training.bat` — **11.3.1 zip 同梱の
オリジナル形そのまま**(4行、引用符なし、`start`のみ):

```bat
@echo off
echo STARTING Training Mode for VSAV (scripts = v11.3.3)
start fcadefbneo.exe vsavj savestates\vsavj_fbneo.fs %cd%\scripts\vsav_training_master_script.lua
exit
```

**教訓(同じ失敗を3回繰り返した):**
- lua パスを**引用符で囲む + `start "" /wait`** にすると FC2 FBNeo の引数解析が
  壊れ、「C:\...\scri is not supported」ダイアログ(32文字で切れたパス)が出る。
  オリジナル形(引用符なし)なら動く。
- バットの改行は **CRLF** 必須(LF だと cmd の解析が壊れる)。
- バットは **C:\fightcade 側のみ**に置く。VsavPrj 側には置かない(誤実行防止)。
- ゲーム起動中・エクスプローラーが scripts 関係フォルダを開いていると
  フォルダ操作は失敗する(過去のマウント式でだけ問題になった。現方式では不要)。

`write_object_to_json_file` はディレクトリを自作しない。**`reversal_logs`
フォルダが無いと logger の書き込みが全て静かに失敗する**(実際、v11.3.3 初回
テストでログが1件も出ず原因特定に手間取った)。

- コラボレータ版の zip にはこのフォルダは同梱されない → インストール時に作ること
- 場所: `scripts\reversal_logs`(= scripts_v11.3.3\reversal_logs)
- **Lua の io の CWD は scripts\ である**(reversal_logs や macro の相対パスの基準)。
  `macro\` フォルダも scripts 配下にある。

## 11.3.2(コラボレータ版)の要点

**※ 11.3.2 の変更は外部からの協力によるもの**

- ダウンリバーサルは `poke_special()`(メモリ書き込み)。
  リバーサル+1 で +0x11E/+0x143/+0x134 を 0 → 通常無敵のない必殺は被弾
- poke 時に向きバイト 0xFF880B を相手向きに → コマ投げにセルフディレクション
- メニューの JSON 書き込みはメニューを閉じた時/終了時のみ
- 詳細: ルートの `VSAV_TRAINING_v11.3.2_CHANGES.md` / `wakeup_reversal_behavior_v11.3.2.md`

## 恒久ルール

- Lua 編集後は必ず `luac5.1 -p`(chocolatey lua51)
- 測定テスト前に `reversal_logs` を `reversal_logs_archive/<版名>_N` へ退避
- スクリプト変更後は Fightcade/FBNeo の完全終了・再起動(ROM リセットでは
  Lua は再読込されない)
- Lua 編集は VsavPrj(作業コピー)→ C:\fightcade(正本)へ **robocopy で同期**
  (`Copy-Item -LiteralPath` に `*` は不可 — ワイルドカード非対応で静かに失敗。
  単ファイル指定は `robocopy <srcdir> <dstdir> <filename>` の形)
- 日本語ドキュメント書き換えに PowerShell の Get-Content/Set-Content を使わない
  (文字化け。Write ツールか UTF-8 明示)
- **推測での修正→テスト→外れる、を繰り返さない。まずログ/データを取る**
  (ユーザ明示要求: 同じミスの繰り返し禁止)
